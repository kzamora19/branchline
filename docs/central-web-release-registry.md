# Branchline central production web release registry

The canonical registry is `/branchline/updates/index.json`. It lists the four established same-origin module release endpoints. Each module owns its increasing release sequence so a delayed deployment cannot advertise an update to an unchanged module. A release manifest is scoped to one module and the production channel; a client rejects wrong-module, staging and lower-sequence manifests. The initial Sales Tracker release 2026112401 is compatible with the new release 2026112402; this is a real subsequent web release. The hosted verification workflow checks all four live manifests, corresponding HTML release stamps and checker assets. No signing key, database, editor credentials or native executable is published here.

For all future releases increment only the affected module's sequence, update stamps and assets together, validate each app's existing tests, and run the hosted verification workflow after publication. Protected Studio restarts go through PTG for new authorization. Save confirmation precedes activation. Browser-installed copies retain their original identities. Native Windows release sequences and signed payloads remain independent of web release labels; no native update is offered until owner signing and real installed-device testing are complete. Hosted checks prove public artifact availability and matching release stamps, not actual authenticated device acceptance or complete historical asset coherence.
